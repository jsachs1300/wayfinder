## Executive Summary

Wayfinder v0.1.0 is an **LLM routing control plane** that intelligently directs requests to the appropriate AI model based on policy constraints, trust preferences, and learned knowledge. Unlike traditional load balancers, Wayfinder delegates routing decisions to a sophisticated router LLM that understands prompt semantics and makes informed recommendations.

**This is a PRE-PRODUCTION RELEASE** suitable for:
- Early adopters and beta testers
- Development and staging environments
- Controlled production pilots with monitoring
- Organizations evaluating LLM routing solutions

This release provides a **production-ready foundation** with comprehensive testing, security hardening, and operational observability. One beta limitation exists (intent-based policy rules) with well-documented workarounds.

---

## What is Wayfinder?

Wayfinder is NOT:
- ❌ A chatbot or conversational interface
- ❌ A prompt optimizer or model execution engine
- ❌ A heuristic-based router using keywords or regex

Wayfinder IS:
- ✅ An **intelligent routing control plane** powered by external LLMs
- ✅ A **policy enforcement layer** ensuring compliance and security
- ✅ A **learning system** that accumulates knowledge from feedback
- ✅ A **production-grade service** with structured logging, health checks, and graceful shutdown

**Core Philosophy:** All routing decisions originate from the router LLM. Policy constrains eligibility. Intent is metadata for analysis. Knowledge is observational telemetry.

## Key Features (Production Ready)

### 1. LLM-Driven Routing

**Status:** ✅ Production Ready

Every routing decision is made by a router LLM (OpenAI or Anthropic), never by local heuristics.

- **Supported Providers:** OpenAI (gpt-4o-mini, gpt-4-turbo, o1-mini, o1) and Anthropic (claude-3-5-sonnet, claude-3-opus)
- **Decision Quality:** Returns primary and alternate model recommendations with confidence scores and explanations
- **Deterministic:** Given the same inputs and state, routing is consistent
- **Contract-Based:** Validates LLM responses against canonical schema with fail-fast on violations

**Example Response:**
```json
{
  "primary": {
    "model": "gpt-4-turbo",
    "score": 8.5,
    "reason": "Excellent reasoning for algorithmic problems"
  },
  "alternate": {
    "model": "claude-3-5-sonnet",
    "score": 7.9,
    "reason": "Strong coding with clear explanations"
  },
  "request_id": "req_a1b2c3d4..."
}
```

### 2. Policy Engine

**Status:** ✅ Production Ready (Global Rules) | ⚠️ Beta (Intent-Based Rules)

Token-scoped policy enforcement ensures compliance and security.

**Production-Ready Features:**
- ✅ **Global Allow/Deny Lists** - Token-level model restrictions
- ✅ **AllowModelsGlobal / DenyModelsGlobal** - Priority-based global rules
- ✅ **Policy Validation** - Fail-fast on invalid configuration
- ✅ **Forced Models** - Bypass routing for specific use cases
- ✅ **Audit Trail** - All policy decisions logged

**Beta Features (See Limitations):**
- ⚠️ ForceModelByIntent (works only with intent "other")
- ⚠️ RestrictModelsByIntent (works only with intent "other")

**Recommended Usage:**
```json
{
  "allowed_models": ["gpt-4-turbo", "claude-3-5-sonnet", "claude-3-opus"],
  "denied_models": ["gpt-3.5-turbo"],
  "policy_rules": [
    {
      "type": "AllowModelsGlobal",
      "models": ["gpt-4-turbo", "claude-3-opus"],
      "priority": 1
    }
  ]
}
```

Curated catalog of 14 production LLM models with lifecycle management.

- **Providers:** OpenAI, Anthropic, Google, Meta, Mistral
- **Validation:** All model identifiers validated at every ingestion point
- **Lifecycle States:** Active, deprecated (with warnings), disabled (rejected)

**Available Models:**

- Anthropic: claude-3-5-sonnet, claude-3-opus, claude-3-haiku

- Meta: llama-3.1-70b, llama-3.1-8b
- Mistral: mistral-large, mistral-medium

### 5. Knowledge Store with Lazy Decay

**Status:** ✅ Production Ready

Accumulates model votes and calculates consensus, not a traditional cache.

- **Scoped Learning:** Global (default) or token-scoped knowledge
- **Agreement Scoring:** Calculates consensus strength across votes
- **Lazy Exponential Decay:** Reduces weight of old data at read time without deletion
- **Confidence Levels:** Strong (≥0.8 + min votes), Moderate (≥0.6), Low (<0.6)
- **Statistics API:** Real-time visibility into knowledge state
- **Long-Lived Data:** Never deletes entries, only reduces influence over time

**Knowledge Scope Options:**
- **Global (Default):** Shared learning across all tokens, maximum network effects
- **Token-Scoped (Enterprise):** Isolated knowledge for compliance, multi-tenancy, custom tuning

### 6. Feedback System

**Status:** ✅ Production Ready

User feedback integration to build knowledge consensus.

- **Ratings:** Positive, negative, neutral
- **Preferred Model:** Override with explicit preference
- **Knowledge Updates:** Automatic vote recording
- **Validation:** Both selected and preferred models validated
- **Scope-Aware:** Feedback respects token knowledge scope
- **Request Linking:** Ties feedback to routing decisions via request_id

### 7. Structured Logging

**Status:** ✅ Production Ready

Privacy-safe observability compliant with REQUIREMENTS.md §12.

- **Privacy-Safe:** Prompt hashing instead of full text, no PII logging
- **Structured JSON:** Machine-parsable logs for analysis
- **Decision Reconstruction:** Full audit trail of routing decisions
- **Metadata Capture:** Intent (internal), confidence, applied policy, knowledge scope
- **Log Levels:** Debug, info, warn, error with configurable thresholds
- **Token-Scoped Logging:** Per-token log level configuration

### 8. Docker Deployment

**Status:** ✅ Production Ready

Production-grade containerization with security hardening.

- **Multi-Stage Build:** Optimized image size (builder + production stages)
- **Non-Root User:** Runs as unprivileged user (UID 1001)
- **Health Checks:** Automatic service health monitoring
- **Graceful Shutdown:** SIGTERM handling with connection draining
- **Redis Integration:** Optional Redis with health checks and persistence
- **docker-compose:** Full stack deployment (wayfinder + redis)
- **Security:** No privileged mode, minimal attack surface

## Beta Features and Known Limitations

### Beta Limitation: Intent-Based Policy Rules (GAP-001)

**Status:** ⚠️ Beta - Documented Timing Limitation

**What Works:**
- ✅ Global allow/deny rules (AllowModelsGlobal, DenyModelsGlobal)
- ✅ Token-level allowed_models and denied_models
- ✅ Forced models (without intent filtering)

**What Has Limitations:**
- ⚠️ **ForceModelByIntent** - Only matches if configured for intent "other"
- ⚠️ **RestrictModelsByIntent** - Only matches if configured for intent "other"

**Why This Happens:**

Intent-based rules face an architectural timing challenge:
1. Intent is inferred **by the router LLM** during routing
2. But policy evaluation happens **before** calling the router LLM
3. Current solution: All requests use placeholder intent "other" for policy evaluation

**Impact:**

Configuring intent-based rules for specific intents (e.g., "coding", "legal", "summarization") will not match as expected. They only work when configured for intent "other".

**Workaround (Recommended):**

Use global allow/deny rules instead of intent-based rules:

```json
{
  "allowed_models": ["gpt-4-turbo", "claude-3-5-sonnet"],
  "policy_rules": [
    {
      "type": "AllowModelsGlobal",
      "models": ["gpt-4-turbo", "claude-3-opus"],
      "priority": 1
    }
  ]
}
```

**Beta Workaround (Intent-Based with "other"):**

If you must use intent-based rules in this release:

```json
{
  "policy_rules": [
    {
      "type": "ForceModelByIntent",
      "intent": "other",
      "models": ["claude-3-opus"],
      "priority": 1
    }
  ]
}
```

This forces the model for ALL requests since all use "other" during policy evaluation.

**Future Fix (P1 Priority):**

This limitation will be addressed in a future version through architectural improvements:
- Two-phase policy filtering (pre-LLM and post-LLM)
- Or restructuring to make intent available earlier in the flow

Tracked as priority 1 for next release. Intent-based rules will become fully functional without workarounds.

## Installation & Deployment

### Prerequisites

- **Node.js 18+** (tested with Node 18, 20, 22)
- **Redis** (optional, falls back to in-memory storage)
- **Docker & docker-compose** (optional for containerized deployment)
- **Router LLM API Key** (OpenAI or Anthropic - REQUIRED)

### Quick Start

#### 1. Standard Node.js Deployment

```bash
# Clone repository
git clone <repository-url>
cd wayfinder

# Install dependencies
npm install

# Configure environment
cp .env.example .env
# Edit .env and set:
#   - ADMIN_API_KEY (required)
#   - ROUTER_LLM_API_KEY (required - get from OpenAI or Anthropic)
#   - ROUTER_LLM_PROVIDER (openai or anthropic)

# Build TypeScript
npm run build

# Run production server
npm start
```

#### 2. Development Mode

```bash
npm run dev
# Server starts with hot reload on port 3000
```

#### 3. Docker Deployment (Recommended for Production)

```bash
# Using docker-compose (includes Redis)
docker-compose up --build

# Or build and run manually
docker build -t wayfinder:0.1.0 .
docker run -p 3000:3000 \
  -e ADMIN_API_KEY=your-key \
  -e ROUTER_LLM_API_KEY=your-router-key \
  -e ROUTER_LLM_PROVIDER=openai \
  wayfinder:0.1.0
```

### Required Environment Variables

```bash
# REQUIRED
ADMIN_API_KEY=your-secure-admin-key-here
ROUTER_LLM_API_KEY=sk-your-openai-or-anthropic-key

# Router LLM Configuration
ROUTER_LLM_PROVIDER=openai              # or 'anthropic'
ROUTER_LLM_MODEL=gpt-4o-mini           # default depends on provider

# Optional but Recommended
REDIS_ENABLED=true                      # use Redis for persistence
REDIS_URL=redis://localhost:6379
LOG_LEVEL=info                          # debug, info, warn, error
PORT=3000
NODE_ENV=production
```

### Router LLM Setup

**Get API Keys:**
- **OpenAI:** https://platform.openai.com/api-keys
- **Anthropic:** https://console.anthropic.com/account/keys

**Supported Models:**
- OpenAI: gpt-4o-mini (default), gpt-4-turbo, gpt-4, o1-preview
- Anthropic: claude-3-5-sonnet (default), claude-3-opus

**Configuration Options:**
```bash
ROUTER_LLM_TIMEOUT=10000               # Request timeout (ms)
ROUTER_LLM_MAX_RETRIES=2               # Retry attempts on failure
ROUTER_LLM_TEMPERATURE=0.0             # 0.0 = deterministic
ROUTER_LLM_MAX_TOKENS=500              # Max response tokens
```

## Security Improvements

This release includes production-grade security hardening:

### Authentication & Authorization
- ✅ **SHA256 Token Hashing:** API tokens hashed before storage using Node's crypto module
- ✅ **Timing-Safe Comparisons:** Protection against timing attacks using `crypto.timingSafeEqual`
- ✅ **Dual Authentication:** Separate admin and user token authentication flows
- ✅ **Token Rotation:** Rotate compromised tokens without reconfiguration

### Operational Security
- ✅ **Non-Root Containers:** Docker runs as unprivileged user (UID 1001)
- ✅ **Privacy-Safe Logging:** Prompt hashing instead of full text, no PII in logs
- ✅ **Fail-Fast Validation:** Invalid configuration rejected immediately, no silent degradation
- ✅ **Structured Errors:** No stack traces or internal details leaked to users

### Input Validation
- ✅ **Zod Schema Validation:** All API inputs validated against strict schemas
- ✅ **Model Registry Validation:** Invalid model identifiers rejected at ingestion
- ✅ **Policy Validation:** Malformed policy rules fail token creation/update
- ✅ **Router LLM Contract Validation:** External LLM responses validated against canonical schema

### Infrastructure Security
- ✅ **Graceful Shutdown:** SIGTERM handling prevents connection loss
- ✅ **Health Checks:** Automated service health monitoring
- ✅ **Redis TLS Support:** Secure connections to Redis (configure via REDIS_URL)
- ✅ **No Hardcoded Secrets:** All credentials via environment variables

## Troubleshooting

### Router LLM Configuration

**Problem:** `RouterLLMError: ROUTER_LLM_API_KEY environment variable is required`

**Solution:**
1. Get API key from OpenAI (https://platform.openai.com/api-keys) or Anthropic (https://console.anthropic.com/account/keys)
2. Add to `.env`: `ROUTER_LLM_API_KEY=sk-your-key-here`
3. Set provider: `ROUTER_LLM_PROVIDER=openai` (or `anthropic`)
4. Restart server

### Intent-Based Policy Not Working

**Problem:** Intent-based policy rules (ForceModelByIntent, RestrictModelsByIntent) don't match as expected

**Solution:** This is the known beta limitation (GAP-001). Use global allow/deny rules instead:

```json
{
  "allowed_models": ["gpt-4-turbo", "claude-3-opus"],
  "policy_rules": [
    {
      "type": "AllowModelsGlobal",
      "models": ["gpt-4-turbo", "claude-3-opus"],
      "priority": 1
    }
  ]
}
```

See [Beta Features and Known Limitations](#beta-features-and-known-limitations) for details.

### Redis Connection Issues

**Problem:** Wayfinder fails to connect to Redis

**Solution:**
```bash
# Option 1: Verify Redis is running
redis-cli ping

# Option 2: Disable Redis and use in-memory storage
# In .env:
REDIS_ENABLED=false
```

### No Models Eligible After Policy

**Problem:** Router LLM has no models to choose from

**Solution:**
```bash
# Check available models
curl http://localhost:3000/admin/models \
  -H "X-Admin-Api-Key: your-admin-key"

# Review token's policy rules
curl http://localhost:3000/admin/tokens/TOKEN_ID \
  -H "X-Admin-Api-Key: your-admin-key"

# Update to allow more models
curl -X PATCH http://localhost:3000/admin/tokens/TOKEN_ID \
  -H "X-Admin-Api-Key: your-admin-key" \
  -H "Content-Type: application/json" \
  -d '{"allowed_models": ["gpt-4-turbo", "claude-3-opus"]}'
```
